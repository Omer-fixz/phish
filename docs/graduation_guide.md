# دليل مشروع التخرج: نظام كشف روابط التصيد الاحتيالي (Phishing Detection System)

هذا المستند يُعد دليلاً شاملاً لشرح الفكرة، البنية الهندسية، آلية عمل الذكاء الاصطناعي، الواجهة البرمجية والموقع الإلكتروني لمشروع التخرج.

---

## 1. الفكرة العامة للمشروع (Project Overview)

**هدف المشروع:**  
بناء نظام كشف ذكي وسريع لروابط التصيد الاحتيالي (Phishing URLs) يعتمد بالكامل على **التحليل اللغوي والمعجمي لنص الرابط نفسه (Lexical Analysis)** دون الحاجة إلى فتح الرابط، تنزيل محتوى الصفحة، أو الاستعلام عن خدمات خارجية (مثل DNS أو WHOIS).

### 🛡️ قاعدة الأمان الرئيسية (Zero-Network Inspection):
النظام لا يتصل إطلاقاً بالموقع المرفق بالرابط. لماذا؟
1. **حماية الخادم والعميل:** فتح رابط خبيث قد يعرض السيرفر للهجمات أو البرمجيات الخبيثة.
2. **السرعة واللحظية:** التحليل النظري لنص الرابط يتم خلال أقل من **5 ميلي ثانية** بدلاً من الانتظار لتنزيل محتوى الويب.
3. **الخصوصية:** عدم تسريب حركة مرور المستخدم أو تتبع الروابط.

---

## 2. المعمارية وهيكل المشروع (System Architecture)

يتكون المشروع من عدة طبقات متكاملة (Modular Architecture):

```
                                  [ المستخدم / المتصفح ]
                                             │
                                     (طلب HTTP / POST)
                                             ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ 1. طبقة الواجهة والـ API (FastAPI - main.py)                                           │
│    - استقبال الرابط وضبط معدل الطلبات (Rate Limiting).                                │
│    - حظر المدخلات غير الصالحة والروابط الطويلة جداً (>2000 حرف).                         │
└──────────────────────────┬─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ 2. مستخرج الخصائص (Feature Extractor - feature_extractor.py)                          │
│    - تحويل الرابط النصي الخام إلى متجه أرقام (Feature Vector).                           │
│    - استخراج 12+ خاصية معجمية (طول الرابط، عدد النطاقات الفرعية، الكلمات المفتاحية...).│
└──────────────────────────┬─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ 3. نموذج الذكاء الاصطناعي (XGBoost Model - model.joblib)                              │
│    - التنبؤ باحتمالية كون الرابط تصيداً (0.0% إلى 100.0%).                                │
│    - استخدام عتبة قرار مخصصة (Decision Threshold = 0.38) لتقليل البلاغات الكاذبة.       │
│    - حساب أهم 3 خصائص أثرت في اتخاذ القرار (Explainability).                            │
└──────────────────────────┬─────────────────────────────────────────────────────────────┘
                           │
                           ▼
[ إرجاع النتيجة بالـ JSON وعرضها بطريقة بصريّة جذابة ومتحركة على الشاشة ]
```

## 3. مراحل عمل النظام بالتفصيل (Detailed Pipeline)

### المرحلة الأولى: استخراج الخصائص (Feature Extraction)
عندما يرسل المستخدم رابطاً مثل: `http://login.paypal.account-update.com/verify`
يقوم ملف `src/feature_extractor.py` بتقسيم الرابط واستخراج الخصائص الرقمية مثل:

1. **طول الرابط (`url_length`):** الروابط الخبيثة غالباً تكون طويلة لإخفاء الوجهة الحقيقية.
2. **عدد النطاقات الفرعية (`subdomain_count`):** كثرة الأجزاء قبل اسم النطاق الرئيسي (`login.paypal...`).
3. **طول النطاق والمسار (`domain_length`, `path_length`).**
4. **عدد الرموز الخاصة (`special_char_count`):** كثرة استخدام `-`, `@`, `?`, `=`, `_`.
5. **وجود كلمات احتيالية شائعة (`sensitive_word_count`):** مثل `login`, `verify`, `secure`, `bank`, `update`.
6. **نسبة الأرقام ونسبة الحروف الأحاديّة (Entropy/Ratios):** التمييز بين الأسماء العشوائية والأسماء البشرية.

---

### المرحلة الثانية: التنبؤ واتخاذ القرار (Machine Learning Prediction)

1. **النموذج المستخدم:** **XGBoost (Extreme Gradient Boosting)**  
   - تم اختياره لأنه أفضل نموذج حقق توازناً ممتازاً بين السرعة والدقة وخفة الوزن مقارنة بـ Random Forest و Logistic Regression.
2. **نتائج النموذج:**
   - **الدقة (Accuracy):** 90.3% (مع التقسيم العادل حسب النطاق `GroupShuffleSplit`).
   - **مقياس AUC-ROC:** 0.9725.
   - **معدل الكشف الخارجي (External Detection):** 93.5% على عينات حية وحديثة من موقع PhishTank و OpenPhish.
3. **تحديد العتبة (Decision Threshold):**
   - العتبة الافتراضية للنماذج عادة تكون `0.5`، لكن تم ضبط العتبة بحسابات دقيقة على مجموعة التحقق لتكون `0.38` لضمان رفع نسبة كشف الروابط الاحتيالية الخطيرة مع الحفاظ على نسبة بلاغات كاذبة منخفضة.

---

### المرحلة الثالثة: التفسيرية والشفافية (Model Explainability)

النظام لا يعطي مجرد "آمن" أو "خبيث" بل يشرح للمستخدم **لماذا** اتخذ هذا القرار:
- يتم حساب مساهمة الخصائص (Feature Importance) في كل فحص.
- يتم إرجاع **أهم 3 خصائص** أدّت إلى النتيجة (مثال: "عدد النطاقات الفرعية مرتفع"، "يحتوي على كلمات مريبة").

---

### المرحلة الرابعة: الواجهة وتجربة المستخدم (Web Interface & API)

1. **السيرفر (FastAPI + Uvicorn):**
   - يقدم الـ API على المسار `/api/v1/predict`.
   - يقدم صفحة الويب على المسار الرئيسي `/`.
2. **التصميم (HTML5 / Vanilla CSS / JS):**
   - تصميم محلي وبسيط بدون مكتبات ثقيلة وخفيف جداً في التحميل.
   - يدعم اللغة العربية بالكامل (RTL Design).
   - متجاوب مع جميع الشاشات (الهواتف، الآيباد، الكمبيوتر).
   - يعرض النتائج بألوان واضحة (الأخضر للروابط الآمنة، والأحمر للروابط الاحتيالية) مع شريط نسبة الثقة.

## 4. تقنيات وأدوات المشروع (Tech Stack)

| المجال | التقنية / المكتبة | السبب / الاستخدام |
|---|---|---|
| **لغة البرمجة** | Python 3.10+ | لغة الأساس المعيارية لذكاء الاصطناعي وتطوير الـ Backend |
| **الذكاء الاصطناعي** | Scikit-Learn / XGBoost / Joblib | لبناء وتدريب وحفظ نموذج التصنيف |
| **معالجة البيانات** | Pandas / NumPy | لتنظيف وتجهيز وتحليل مصفوفات الخصائص |
| **خادم الـ API** | FastAPI / Uvicorn | أسرع إطار عمل Python مخصص لبناء REST APIs مع إمكانية التوثيق التلقائي |
| **واجهة المستخدم** | HTML5 / CSS3 / JavaScript | لبناء موقع ويب عصري، تفاعلي ومستجيب دون تعقيدات |
| **الاختبار والتحقق** | Pytest | يحتوي المشروع على أكثر من 110 اختبارات آليّة لضمان الجودة وعدم حدوث أخطاء |

## 5. ميزات وقوة المشروع للعرض في التخرج (Project Highlights)

1. **معيار عدم التداخل (No Domain Leakage):** تم تقسيم بيانات التدريب والاختبار عبر `GroupShuffleSplit` بحسب اسم النطاق، مما يضمن أن النموذج يختبر قدرته على كشف نطاقات جديدة لم يرها من قبل وليس مجرد حفظ النطاقات المكررة.
2. **نظام التفسير الذكي (Explainable AI):** توضيح أسباب القرار للمستخدم للزيادة من موثوقية النظام.
3. **تكامل تام (End-to-End System):** يغطي المشروع الدورة الكاملة (جمع البيانات ⬅️ استخراج الخصائص ⬅️ التدريب والتقييم ⬅️ الـ API ⬅️ موقع الويب).
4. **أمان عالي للخدمة:** تفعيل الـ Rate Limiting وحجم المدخلات لمنع هجمات حجب الخدمة (DoS).

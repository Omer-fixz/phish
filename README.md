# نظام كشف روابط التصيد الاحتيالي

كشف روابط التصيد بتحليل نص الرابط وحده، دون أي اتصال بالموقع المفحوص.

---

## النتائج

| المؤشر | القيمة |
|-|-|
| النموذج | XGBoost (depth=6, lr=0.1) |
| Accuracy (تقسيم حسب النطاق) | 0.9029 |
| Precision / Recall / F1 | 0.8796 / 0.9222 / 0.9004 |
| ROC-AUC | 0.9725 |
| عتبة القرار | 0.38 (مختارة من مجموعة التحقق) |

**التقييم الخارجي** على مصادر لم يرها النموذج إطلاقاً:

| المصدر | نسبة الكشف |
|-|-|
| PhishTank (أحدث 3000 رابط مؤكد) | **0.9357** |
| منها على نطاقات جديدة كلياً | 0.9246 |
| OpenPhish (مصدر مستقل) | 0.9467 |

> الدقة بتقسيم عشوائي تبلغ 0.9420، وهو **رقم متضخّم لا يُعتمد**: 69.6% من الروابط تقع في نطاقات مكررة، فالتقسيم العشوائي يضع النطاق نفسه في التدريب والاختبار.

## التشغيل

```bash
python scripts/01_build_dataset.py
```
يبني `data/processed/dataset_v2.csv` من الروابط الخام بالمستخرج الرسمي.

```bash
python scripts/02_verify_dataset.py
```
يثبت أن الملف المبني يطابق ما ينتجه المستخرج اليوم. **شغّله بعد أي تعديل على `feature_extractor.py` وقبل التدريب.**

```bash
python scripts/03_eda.py
```
التحليل الاستكشافي: 5 رسومات في `reports/figures/` وجدول في `reports/tables/`.

```bash
python scripts/04_train_model.py
```
يقارن أربعة نماذج، يختار العتبة من مجموعة التحقق، ويحفظ `models/model.joblib`.

```bash
python run_api.py
```
يشغّل الخادم على `http://127.0.0.1:8000` — الواجهة على `/` والتوثيق التفاعلي على `/docs`.

كل السكربتات تعمل من أي مجلد لأن المسارات مطلقة عبر `src/paths.py`.

## القرارات المنهجية

1. **التقسيم حسب النطاق** (`GroupShuffleSplit`) لا عشوائياً، مع تحقق برمجي من عدم تداخل النطاقات بين المجموعات الثلاث.
2. **مستخرج خصائص واحد** (`src/feature_extractor.py`) يُستورَد في التدريب والتشغيل معاً. اختلافه بين المرحلتين أشهر عطل في هذا النوع من المشاريع، و`test_integration.py` يمنع تكراره.
3. **العتبة تُختار من مجموعة التحقق** بقاعدة: أعلى استدعاء بشرط ألا تتجاوز الإنذارات الكاذبة 10%، ثم تُحفظ داخل النموذج ليقرأها التطبيق — فيستحيل أن تختلف عتبة التقييم عن عتبة التشغيل.
4. **الخصائص الميتة تُحذف**: `has_ip_address` و`is_https` قيمتهما صفر في كل الصفوف.
5. **لا يُفتح الرابط إطلاقاً** — لا WHOIS ولا تنزيل صفحة ولا تتبع إعادة توجيه. كل شيء من نص الرابط.

## حدود النظام

1. الروابط في المصدر الأصلي بلا بروتوكول، لذلك `is_https` ثابتة صفراً وحُذفت.
2. لا يوجد أي رابط قائم على عنوان IP، لذلك `has_ip_address` ثابتة صفراً وحُذفت.
3. الروابط الشرعية في المصدر أقصر بكثير من الاحتيالية، وهو انحياز مصدر يجعل `url_length` أقوى مما تستحق.
4. أُضيف 5,000 نطاق شرعي بلا مسار من قائمة تارانكو لسد فجوة: كانت النطاقات بلا مسار 0.35% فقط من الشرعي مقابل 8.60% من التصيد، فكان النموذج يصنّف `google.com` تصيداً باحتمال 0.98.
5. **نسبة الإنذارات الكاذبة المعتمدة هي 11.5%** المقاسة على مجموعة الاختبار الأصلية. الرقم المنخفض في التقييم الخارجي (0.13%) متفائل لأن جانبه الشرعي نطاقات مجردة سهلة، ولا يصح الاستشهاد به.
6. **حد نظري للمنهج**: الروابط الفائتة غالباً مواقع شرعية مخترقة تستضيف صفحة تصيد، ونصّ الرابط فيها خالٍ من أي دليل. لا يمكن لأي نموذج معجمي كشفها مهما تحسّن — وهذا مبرر دمج فحص عمر النطاق أو الشهادة مستقبلاً.
